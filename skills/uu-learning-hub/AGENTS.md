# AGENTS.md — 悠悠学习项目执行规则（V4）

## 当前执行入口
当前可执行入口只有：
`skills/uu-learning-hub/SKILL.md`

V1/V2/V3均为历史档案，不作为当前执行入口。

## 自主执行原则
1. 信息足够时直接继续，不为流程重复确认。
2. 只有缺失信息会实质改变课程难度、事实正确性、安全结果或外部持久化写入时才提问。
3. 可标记“未知/待观察”而继续的，不阻断任务。
4. 不要求用户重复提供项目中已有信息。
5. 非关键工具/缓存/子代理不可用时自动降级。

## 学习计划的模式解释
“今天的学习计划”“今日计划”“下一天”“继续一天”“学习日N”都属于七天学习系统。

单日请求的含义是：
> 读取当前周状态 → 生成下一个学习日。

不得：
- 把单日请求当成孤立随机练习；
- 重新启动一周；
- 跳过必要的C/A/B/D/F/E；
- 忽略上一学习日结果。

## 多代理与降级
七天/单日学习计划：**C → A → B → D → F → E → Controller**

- 有真实子代理：优先实际委派。
- 无真实子代理：主Agent按相同职责串行执行，不再确认，不假装有独立代理。
- “无需多代理即可”：单Agent完成，但保留质量门禁。

新鲜事：**B → F → E-lite**  
推荐：**C-lite（必要时）→ B → E-lite**

## 测试数据
用户明确说“测试/不记录”时：
- 测试数据不得进入正式能力画像；
- 不计入正式学习日；
- 不影响正式基线；
- 若测试学习计划输出，仍生成与正式流程一致的Excel，但标记“测试版”。

## 能力评估
正式学习计划先由C做能力充分性检查：
- 足够：直接继续；
- 少量关键未知：最少量复测；
- 无可靠数据：自适应评估。

目标是“信息足够”，不是“必须问题”。

## 来源与证据
B默认：
1. 最新来源原始资料缓存；
2. 缓存失败 → 原始项目文件；
3. 精确数字/图表/原话/OCR异常/冲突 → 原文件；
4. 时间敏感新鲜事 → 近期可靠公开来源。

## 连续性
稳定项降频/升级；临界项变式复现；弱项必须被处理；挑战项继续上探。

弱项的“处理”可为：
- 继续训练
- 降级训练
- 换表征
- 暂缓并说明理由

## E审查
单项可 PASS / FAIL / N/A；最终只能 PASS / REVISE。

E必须检查：
- 日内和日间连续性
- 周间连续性
- 系统性
- 题目逻辑
- 表述清晰
- 英语生活化
- 难度
- 真假掌握
- 家长可执行性
- 当日/周目标可验证

## Excel交付硬规则
学习计划经E PASS后，Controller必须生成Excel。

### 单日
即使用户只说“今天的学习计划”，也必须输出 `.xlsx`，不能只在聊天里列题。

单日Excel至少含：
- 今日总览
- 今日详细课表
- 家长记录
- 日闭环研判

### 七天
七天Excel至少含9个既定工作表。

测试模式也生成Excel，但文件名和表内明确标记“测试版”。

如果Excel生成工具临时失败，可说明失败并尽可能恢复/重试；不能把“聊天里的题目”当作已经完成正式Excel交付。

## 一天与一周
不按现实日期：
- 出题/任务 → UU回答或执行 → 记录 → 当日研判 = 1个学习日闭环。
- 累计7个学习日闭环 = 1周。
- 第7个闭环后必须生成周总结。

## 周总结
保存一周全部题目、关键回答、三科能力变化和下一周继承项。数据不足标记未知，不虚构。

## 外部持久化审批
写入/修改GitHub、删除/覆盖外部文件、创建commit等需要用户当前任务明确授权。

生成课程、Excel、总结、能力画像本身不需要再次审批。

## 任务完成原则
用户请求正式交付物时，只要关键输入足够，就尽可能一次完成。
